# Executive Summary

trame-vtklocal (see [repository](https://github.com/Kitware/trame-vtklocal)) is the Python/trame delivery layer for browser-side rendering with VTK-WASM. It accepts an ordinary server-side `vtkRenderWindow`, serializes the reachable VTK object graph, reconstructs that graph in a browser WebAssembly runtime, binds it to an HTML canvas, and renders locally through WebGL or WebGPU. Users retain Python ownership of their VTK or PyVista pipeline and do not need to reproduce the scene in JavaScript.

Between June 2025 and August 3, 2026, the repository advanced from `v0.14.0` to `v1.1.0`, with approximately 173 commits, 30 merged pull requests, and 33 version tags in the audited period. The project added client-to-VTK method calls, picking, shared runtimes, concurrent loading, scene patching, export and standalone viewing, custom-module serialization, progress and memory reporting, WebXR, automatic resizing, and versioned web assets. The June–July 2026 1.x transition adopted VTK-WASM 2 and exposed WebGL/WebGPU, synchronous/asynchronous execution, wasm32/wasm64, remote-session access, explicit disposal, multi-view support, and unified VTK 9.7 archive handling.

The architecture separates state from binary data. `vtkObjectManager` serializes object properties, references, and modification times; data arrays are transferred as content-addressed blobs. The browser's remote session pulls only required or changed state, keeps interactive camera work local, and requests new data when the Python pipeline updates. `LocalView` wraps the transport, runtime configuration, canvas lifecycle, progress UI, selection, and synchronization in a trame widget.

The project now serves a second role as the end-to-end validation layer for VTK-WASM. Playwright visual-regression tests cover WebGL and WebGPU, wasm32 and wasm64, synchronous and asynchronous modes, geometry changes, mount/unmount/remount, multiple views, volume paths, and Linux/macOS/Windows runners. These tests have exposed core VTK ownership, serialization, mapper, and interactor defects. Remaining work includes WebGPU volume rendering, broader class/widget/text coverage, stronger nightly VTK-to-trame contract testing, PyVista integration, and reconciliation of version-support documentation.
