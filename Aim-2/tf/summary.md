# Executive Summary

Aim 2 of the VTK Innovation project uses AI both to improve visualization and to make AI behavior easier to understand. We have continued the AI transfer-function thrust during 2026. This work addresses a persistent volume-rendering problem: a carefully designed mapping from scalar values and gradients to color and opacity often fails when applied to another patient, scanner, acquisition protocol, or simulation state.

The project builds on the Transferring Transfer Functions method of Saravi et al. A known transfer function for a reference volume guides a pointwise neural model that predicts a transfer function for a target. The demonstrated experiment uses a GE 3T brain MRI with a segmentation mask and an eight-control-point, hand-authored 3D Slicer `.vp` function as its reference. A Philips 3T scan from another subject is rigidly registered onto the same grid. A shared-slice dataset selects the same random axis, interior slice, and square crop from both scans. The target supplies normalized scalar intensity and gradient magnitude; the reference supplies five rendered channels: RGB, scalar opacity, and gradient opacity. No paired voxel labels are used, and the model never sees the reference volume's scalar values.

The model has two branches. `ColorOpacityNet` maps scalar intensity to RGB and scalar alpha; `GradientOpacityNet` maps gradient magnitude to gradient alpha. Each branch uses a 13-dimensional Fourier embedding, four 64-unit hidden blocks with layer normalization and ReLU, and sigmoid-bounded outputs. VTK multiplies scalar and gradient alpha at render time. The pointwise design lets the same weights process `[N,2,H,W]` slice batches during training and a flat 256-sample grid during export.

The focused implementation removes the costly full 3D optimization loss and trains on corresponding rendered slices with five-channel supervision. Its objective is `0.2 x L1 + 0.8 x (1 - SSIM)`. L1 retains per-pixel fidelity, while SSIM discourages the blurred, averaged tissue colors that L1 alone can produce. The documented run used Adam at `1e-3`, `ReduceLROnPlateau`, two epochs of 1,024 sampled slices, and batches of 16. It exports a 256-point lookup table as ParaView JSON or Slicer `.vp`.

Progress moved from code recovery and refactoring in February to a private repository and application work in March, a working interface skeleton in May, and an end-to-end demonstration in June. The trame and VTK-WASM application synchronizes camera, crop planes, and slice index across reference and target views. Linear intensity remapping assigned tissue classes incorrectly. The untrained network began as a uniform green result; by roughly 35% of the run, orange and yellow cortex appeared; and after two epochs the learned Philips rendering recovered the reference's cyan background and blue, red, and yellow tissue organization. In the live meeting demonstration, the two epochs took about 20 seconds, but that observation is hardware-specific.

The prototype is promising but not yet a general-purpose inference system. Registration and resampling remain important constraints, training requires significant GPU memory, gradient-opacity controls need better presentation, and broader validation is required. Later 2026 discussions began exploring extension to scientific simulation and time-varying CFD data, but that work remains a research direction rather than a delivered capability. The immediate objective is to complete, document, validate, and release the focused trame workflow so the VTK and medical-imaging communities can evaluate it.
